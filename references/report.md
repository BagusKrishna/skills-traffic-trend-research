# Research report fields

Adapt the structure to the question. Do not pad a small or poorly supported result to fill a fixed table size.

## Scope and coverage

Record run date/time, timezone, geography, language, topic, exact research/comparison windows, and mode. Identify inspected sources and unavailable/stale sources. Distinguish 'not researched' from 'researched but no evidence found.'

## Evidence ledger

| Signal/query | Source URL | Source data as of / period | Geography | Metric + unit | Observation | Evidence type / limitation |
|---|---|---|---|---|---|---|

Use actual values only when observed. Use 'unavailable' where volume/growth cannot be obtained. Include publication and retrieval dates if the difference matters. Distinguish platform observation, provider estimate, third-party report, first-party analytics, and inference. Keep direct citations close to claims.

## Opportunity comparison

| Concept + user task | Supporting signals | Acquisition route | Return trigger | Named competitors / proposed gap | Maintenance/cost | Monetization fit | Confidence + open question |
|---|---|---|---|---|---|---|---|

For the strongest concepts state a narrow MVP and a small validation experiment. If scoring helps, use a documented rubric and mark subjective ratings; do not create precise-looking forecasts from qualitative scores. High confidence means evidence agrees on the stated claim, not that the product will succeed.

## Recommendation and next evidence

Explain the best fit for the user's goal, the evidence that could change the decision, and any seasonal or access limitations. Avoid equating market size with reachable traffic. List source URLs, timestamps/ranges, and useful search queries so another agent can reproduce the work. Save the dated report in the workspace's documentation location and return its path.
